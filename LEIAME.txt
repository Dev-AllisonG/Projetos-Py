============================================================
 PASSO 1 — Criar o bot no Telegram (2 min)
============================================================
1. Abra o Telegram e procure por:  @BotFather
2. Envie o comando:  /newbot
3. Escolha um nome (ex: Radar Insider)
4. Escolha um username terminando em "bot" (ex: radarinsider_seunome_bot)
5. O BotFather responde com um TOKEN parecido com:
      <BOT_TOKEN do arquivo .env>
   → COPIE esse token

============================================================
 PASSO 2 — Descobrir o CHAT_ID DO GRUPO (2 min)
============================================================
O BOT_TOKEN já veio preenchido no bot.py. Falta só o ID do
GRUPO (que é um número NEGATIVO, ex: -100xxxxxxxxxx).

Jeito fácil — use o script pronto:
1. Adicione o seu bot DENTRO do grupo do Telegram
2. Envie qualquer mensagem no grupo (ex: "oi" ou /start)
3. No terminal, rode:
      python pegar_chat_id.py
4. O script mostra o ID do grupo marcado com uma seta
5. Copie o número negativo

Jeito manual (alternativa):
1. Abra no navegador (com o bot já dentro do grupo e uma
   mensagem enviada lá):
      https://api.telegram.org/botSEU_TOKEN/getUpdates
2. Procure por:  "chat":{"id":-100xxxxxxxxx,"title":"Nome do Grupo"
3. Copie o número negativo (COM o sinal de menos)

Se nada aparecer: fale com @BotFather → /setprivacy →
escolha seu bot → Disable → envie outra mensagem no grupo
e repita.

============================================================
 PASSO 3 — Configurar o bot (30 seg)
============================================================
Abra o arquivo bot.py em qualquer editor (Bloco de Notas serve)
e preencha a linha do CHAT_ID:

   CHAT_ID = "-100xxxxxxxxxx"    ← id do grupo (negativo)

(O BOT_TOKEN já está preenchido)

============================================================
 PASSO 4 — Rodar
============================================================
No terminal (Prompt de Comando / PowerShell / Terminal):

   pip install -r requirements.txt
   python bot.py

Pronto! Você recebe a ativação no Telegram.
Deixe a janela aberta. Para parar: Ctrl+C ou feche o painel
(os dados são salvos automaticamente nos dois casos).

⚠️ IMPORTANTE (v4.1+): a pasta radar/ TEM que ficar ao lado do

E a pasta radar/ juntos. Seu radar_dados.json NÃO é tocado.

============================================================
PIPELINE OWNERSHIP + RUNTIME OBSERVABILITY (v9.6.1)
============================================================

Objetivo desta secao: acabar com "multiplas fontes de verdade". Hoje
existem quatro pipelines no processo e cada uma tem dono definido.

------------------------------------------------------------
LEGACY (radar v4.8/v7.0) - UNICA PIPELINE OPERACIONAL
------------------------------------------------------------
source:       polling HTTP (radar/rpc.py) + fila do WebSocket legado
consumer:     bot.ciclo() -> radar/analise.py
persistence:  radar_dados.json (estado vivo) + radar_historico.db
alert path:   radar/telegram.py  <-- SO ELA ALERTA
responsavel:  descoberta de wallets, scoring, poda, alertas

------------------------------------------------------------
FOUNDATION (Fases 1.2-1.6)
------------------------------------------------------------
source:       raw_events de data_foundation.db
consumer:     radar/foundation/worker.py (thread "foundation-worker")
persistence:  data_foundation.db (entity state, retention)
alert path:   NENHUM
responsavel:  parsing, EntityState, retencao, query engine

------------------------------------------------------------
INGESTION V8 (Fase 1 da nova arquitetura) - SHADOW
------------------------------------------------------------
source:       WebSocket proprio + RPC proprio
consumer:     thread "ingestion-v8"
persistence:  data_foundation.db (raw_events, canonical_transactions)
alert path:   NENHUM enquanto INGESTION_V8_MODE != active
responsavel:  raw ingestion e canonicalizacao

------------------------------------------------------------
GRAPH (Fase 4)
------------------------------------------------------------
source:       eventos ja normalizados
consumer:     radar/ingestion/graph/ (thread "graph-store")
persistence:  arestas + edge_evidence na feature store
alert path:   NENHUM
responsavel:  relacoes entre wallets e funding graph

------------------------------------------------------------
AUDITORIA DE DOUBLE PROCESSING (requisito 18)
------------------------------------------------------------
A pergunta era: legacy + v8 processariam o mesmo evento duas vezes?

EVENTO DUPLICADO:   SIM. As duas assinam os mesmos programas na Solana,
                    entao a mesma signature chega nas duas.
RPC DUPLICADO:      SIM. Sao clientes RPC distintos, sem cache comum.
WRITE DUPLICADO:    NAO. Bancos e tabelas diferentes
                    (radar_historico.db x data_foundation.db).
DISCOVERY DUPLICADA:NAO. A v8 nao escreve em estado.WALLETS.
ALERTA DUPLICADO:   NAO. Nao existe caminho de codigo da v8 ate
                    radar/telegram.py.

CONCLUSAO: ativar INGESTION_V8_MODE=active HOJE seria seguro quanto a
alertas, mas dobraria o custo de RPC sem entregar valor operacional.
Por isso o modo recomendado agora e "shadow": ele mede a diferenca
entre as duas pipelines antes de qualquer migracao.

INGESTION_V8_MODE:
  off     nao inicia
  shadow  ingere e persiste, mas nao alerta e nao toca no estado legado
  active  pipeline operacional (NAO usar antes de validar o shadow)

A flag antiga INGESTION_V8_ATIVO=True agora cai em SHADOW, nunca direto
em operacional.

============================================================
 RPC: PUBLICO vs DEDICADO (v9.7.1)
============================================================
O endpoint publico (api.mainnet-beta.solana.com) serve para TESTE.
Em operacao (backfill de gaps, historico), ele responde 429 (rate
limit) por design — e ESPERADO, nao e falha do bot: o bot faz backoff
com Retry-After, reduz a taxa e continua ate completar.

Para operacao continua, defina ANTES de iniciar (nunca no codigo):
    set RPC_HTTP_URL=https://seu-endpoint-dedicado
    set RPC_WS_URL=wss://seu-endpoint-dedicado
(Helius/QuickNode/Triton etc. Nunca cole a chave em arquivo do projeto.)

============================================================
 MODO DE OPERACAO: HEADLESS (PADRAO) vs PAINEL VISUAL (v9.7.3)
============================================================
O bot roda SEM janela por padrao — operacao continua 24/7, a janela
nao segura mais o processo. Para abrir o painel visual:
    set RADAR_GUI=1
    INICIAR_BOT.bat
Fechando a janela do painel: o encerramento e ORDENADO — o ciclo
corrente termina, o estado e salvo, e o .bat NAO reinicia (exit 43).
Se a janela for fechada DURANTE o boot, o bot apenas sai, sem tocar
no estado. Queda inesperada: o .bat reinicia com backoff (teto: 5).
